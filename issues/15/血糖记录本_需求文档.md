# 血糖记录系统 · 需求文档（PRD）

**项目名称**：血糖记录本（Glucose Tracker）  
**版本**：v2.0  
**仓库地址**：https://github.com/jeremyjia/Corpus  
**数据存储**：GitHub Issue #15 Comments  
**部署方式**：GitHub Pages（静态单文件 HTML）  
**文档日期**：2026-10-31

---

## 1. 项目概述

### 1.1 背景与目标
需要一个轻量、无后端的个人血糖管理工具，用于记录日常血糖测试数据。数据以 GitHub Issue Comment 的形式持久化存储，利用 GitHub API 完成读写，零服务器成本，天然版本可追溯。

### 1.2 核心用户场景
- 记录不同时间点的血糖值（空腹、餐后1h、餐后2h、随机、睡前）
- 记录被测人姓名，支持多人共用同一 Issue 区分数据
- 记录饮食内容与备注信息
- 查看统计概览与按人分组的记录列表
- 通过浏览器随时访问、添加、删除记录

### 1.3 技术约束

| 约束项 | 说明 |
|--------|------|
| 前端形态 | 纯 HTML + CSS + JS，单文件，无构建工具 |
| 数据存储 | GitHub Issue Comments（JSON 格式） |
| 认证方式 | GitHub Personal Access Token（前端 localStorage + 内置默认值） |
| 部署平台 | GitHub Pages |
| 默认仓库 | `jeremyjia/Corpus` |
| 默认 Issue | #15 |
| 默认被测人 | Jeremy |
| Token 处理 | 前端拆分拼接存储，防止静态扫描直接提取 |

## 2. 功能需求

### 2.1 页面结构与交互流程

```
┌─────────────────────────────────────────────┐
│  页面加载                                     │
│  ├── 读取 localStorage 配置                   │
│  │   └── 无配置 → 使用内置默认值自动连接       │
│  ├── 主界面立即可见（统计栏 + 表单 + 列表）     │
│  └── 右上角 ⚙️ 按钮 → 展开/收起配置面板        │
└─────────────────────────────────────────────┘
```

**原则**：主界面优先，配置为次要入口，不阻断正常使用。

### 2.2 配置管理

#### 2.2.1 配置项

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| GitHub Token | string (password) | 拆分拼接内置值 | 留空即使用默认值 |
| 仓库所有者 | string | `jeremyjia` | |
| 仓库名称 | string | `Corpus` | |
| Issue 编号 | number | `15` | |
| 默认被测人 | string | `Jeremy` | 新增记录时的默认归属 |

#### 2.2.2 Token 存储策略

```javascript
// 拆分拼接，防止源码静态扫描直接暴露完整 token
const DEFAULT_TOKEN = [
  'ghp_', 'Od6GW3J2', 'NiP01Zsz',
  'g9JQV0am', 'znUxhF33', 'iBES'
].join('');
```

- 用户输入的 Token 优先；留空则使用内置默认值
- 所有配置持久化到 `localStorage`

#### 2.2.3 连接验证
点击"连接"按钮后：
1. 调用 GitHub API `GET /repos/{owner}/{repo}/issues/{number}`
2. 成功 → 显示绿色状态提示，展开主内容区，自动加载记录
3. 失败 → 显示红色错误信息

### 2.3 数据模型

#### 2.3.1 单条记录结构（JSON）

```json
{
  "id": "uuid-v4",
  "patient": "Jeremy",
  "timestamp": "2026-10-31T14:30:00+08:00",
  "glucose": 5.6,
  "measurementType": "餐后1h",
  "food": "米饭、青菜、鸡胸肉",
  "notes": "饭后散步30分钟",
  "createdAt": "2026-10-31T14:35:00.000Z"
}
```

#### 2.3.2 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| id | ✅ | string (UUID) | 唯一标识，用于删除定位 |
| patient | ✅ | string | 被测人姓名，默认 Jeremy |
| timestamp | ✅ | ISO 8601 | 测量时间（datetime-local 输入） |
| glucose | ✅ | number | 血糖值，单位 mmol/L |
| measurementType | ✅ | enum | 见 2.3.3 |
| food | ❌ | string | 饮食内容 |
| notes | ❌ | string | 备注（运动、心情等） |
| createdAt | ✅ | ISO 8601 | 记录创建时间 |

#### 2.3.3 测量类型枚举

| 值 | 标签样式 | 血糖参考范围（mmol/L） |
|----|---------|----------------------|
| 空腹 | 蓝色 | 正常 3.9~6.1 / 警告 6.1~7.0 / 危险 <3.9 或 >7.0 |
| 餐后1h | 粉色 | 正常 <7.8 / 警告 7.8~11.1 / 危险 >11.1 |
| 餐后2h | 黄色 | 正常 <7.8 / 警告 7.8~11.1 / 危险 >11.1 |
| 随机 | 绿色 | 正常 <7.8 / 警告 7.8~11.1 / 危险 >11.1 |
| 睡前 | 紫色 | 同随机 |

#### 2.3.4 GitHub Comment 存储格式

```markdown
<!-- GLUCOSE_RECORD -->
```json
{ ... 完整记录 JSON ... }
```
```

- 以 HTML 注释 `<!-- GLUCOSE_RECORD -->` 作为标记，便于过滤识别
- JSON 包裹在 fenced code block 中，方便解析与人工阅读

### 2.4 添加记录

#### 2.4.1 表单字段

| 字段 | 控件 | 默认值 |
|------|------|--------|
| 被测人 | text input | 配置中的默认被测人（Jeremy） |
| 血糖值 | number (step=0.1) | 空，必填 |
| 测量类型 | select | 空腹 |
| 测量时间 | datetime-local | 当前本地时间 |
| 饮食内容 | text input | 空 |
| 备注 | textarea | 空 |

#### 2.4.2 提交行为
1. 前端校验（必填项）
2. 生成 UUID
3. POST 到 GitHub API 创建 Issue Comment
4. 成功 → Toast 提示"✅ 记录已保存"，清空血糖/饮食/备注字段，保留被测人和时间，刷新列表
5. 失败 → Toast 提示错误信息

---

### 2.5 记录列表展示

#### 2.5.1 分组规则
- **按 `patient` 字段分组**
- 每组标题：`👤 {姓名} · {N}条 · 均值 {avg}`
- 组间排序：按该组最新一条记录的时间倒序
- 组内排序：按 `timestamp` 倒序（最新在前）
- **向后兼容**：无 `patient` 字段的老记录自动归入默认被测人（Jeremy）

#### 2.5.2 单条记录卡片

```
┌──────────────────────────────────────────┐
│  5.6    空腹  10/31 14:30               │
│          🍽️ 米饭、青菜、鸡胸肉            │
│          饭后散步30分钟                    │
│                              [删除]       │
└──────────────────────────────────────────┘
```

- 血糖值根据测量类型 + 数值自动着色（绿/黄/红）
- 测量类型显示为彩色标签
- 删除按钮调用 GitHub API DELETE comment

---

### 2.6 统计栏

分为两个区块：

| 区块 | 指标 |
|------|------|
| 📊 全部 | 总记录数 / 全部平均值 / 近7天平均 / 范围（min~max） |
| 👤 {默认被测人} | 该人记录数 / 该人平均值 / 该人近7天平均 / 该人范围 |

> 近7天 = 以当前时间为基准，往前推 7 天的记录。

---

### 2.7 删除记录

1. 点击删除按钮 → 确认弹窗
2. 确认后调用 `DELETE {comment_url}`（GitHub API）
3. 成功 → Toast 提示，刷新列表
4. 失败 → Toast 错误提示

## 3. 非功能需求

### 3.1 兼容性
- 现代浏览器（Chrome / Firefox / Safari / Edge 最新版）
- 移动端响应式布局（< 600px 自适应）

### 3.2 性能
- Issue Comments 分页加载（每页 100 条）
- 前端排序与分组，无后端计算

### 3.3 安全
- Token 不硬编码完整字符串（拆分拼接）
- Token 存储于 localStorage（用户可控清除）
- ⚠️ 建议：使用 Fine-grained Token，仅授权 `jeremyjia/Corpus` 单仓库 Issues 读写权限

### 3.4 可访问性
- 表单 label 关联
- 键盘可操作
- 颜色 + 文字双重标识（不只靠颜色传达状态）

---

## 4. 异常处理

| 场景 | 处理方式 |
|------|---------|
| GitHub API 限流 (403) | Toast 提示"API 限流，请稍后重试" |
| Token 无效 | 配置区红色错误提示 |
| Issue 不存在 | 配置区红色错误提示 |
| 评论解析失败 | 控制台 warn，跳过该条，不影响其他记录 |
| 网络异常 | Toast 提示"网络错误" |
| 删除失败 | Toast 提示具体错误信息 |

## 6. 附录

### 6.1 GitHub API 端点

| 操作 | 方法 | 路径 |
|------|------|------|
| 验证连接 | GET | `/repos/{owner}/{repo}/issues/{number}` |
| 获取 Comments | GET | `/repos/{owner}/{repo}/issues/{number}/comments?per_page=100&page={n}` |
| 创建 Comment | POST | `/repos/{owner}/{repo}/issues/{number}/comments` |
| 删除 Comment | DELETE | `{comment_url}`（从列表响应中获取） |
